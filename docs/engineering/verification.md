# بررسی نسخه

## رزرو عملیاتی — ۲۴ اکتبر ۲۰۲۶

نسخه NestJS و PostgreSQL جایگزین پیش‌نمایش محلی رزرو شده است. آزمون‌های interface واقعی HTTP، ۱۲ درخواست هم‌زمان روی بازه هم‌پوشان، idempotency نگه‌داشت/تأیید/لغو، انقضا و آزاد شدن ظرفیت، شناسه میز یکسان در دو مکان، عضویت سازمان، مجوز مکان، capability مهمان، ورود و خروج session و ثبت حضور را بررسی می‌کنند. هر اجرا دیتابیس تصادفی مستقل می‌سازد؛ داده دیتابیس پیکربندی‌شده truncate نمی‌شود. کل تست‌ها ۳۹ مورد هستند: ۴ enforce معماری، ۴ نمایشگر، ۲۲ کافه/رابط مشتری و ۹ integration PostgreSQL.

در Chrome دسکتاپ و عرض ۳۹۰، فرم مشتری از انتخاب میز تا زمان سرور، نگه‌داشت، اطلاعات تماس با ارقام فارسی، تأیید، بازکردن دوباره و لغو بررسی شده است. فرم انتظار و خطای شبکه دارد و پاسخ گم‌شده با همان کلید فرمان بازیابی می‌شود. نشست مهمان پس از reload همان زبانه قابل پیگیری است. ورود کارکنان، فهرست روز، ثبت حضور، لغو، خروج و تغییر روز از مرورگر با Nest/PostgreSQL بررسی شده‌اند.

منبع زمان و ظرفیت API است. دیتابیس exclusion constraint و قفل تراکنش میز دارد. تماس مهمان هنوز احراز پیامکی نمی‌شود؛ کد پیگیری عمومی مجوز دسترسی نیست. جزئیات راه‌اندازی و حدود فاز در [راهنمای رزرو](../guides/running-reservations.md) قرار دارند. یادداشت‌های پایین شواهد نسخه‌های قبلی‌اند و ادعای «بدون API / رزرو فقط نمایشی» برای نسخه کنونی معتبر نیست.

# بررسی کیفیت دمو

## جداسازی چندصنفی — ۲۴ اکتبر ۲۰۲۶

`npm test` هر ۲۴ آزمون را با موفقیت اجرا کرد: ۴ آزمون enforce interfaceها، ۴ آزمون قرارداد مستقل صحنه و ۱۶ آزمون رفتار کافه/هندسه/رزرو نمایشی. `npm run lint` شامل بررسی importهای resolveشده، `npm run check-types` برای همه workspaceهای مصرف‌کننده و build تولید نیز موفق بودند. مسیرهای عمومی فعلی و aliasها همچنان در خروجی تولید حاضرند.

در مرورگر، کافه برگ تا انتخاب میز ۲ و خلاصهٔ پیش‌نمایش رزرو بررسی شد. کاما تا انتخاب میز ۱۳ و رفتن به کنار آن بررسی شد؛ خطای کنسول در این مسیر مشاهده نشد. fixture مسکونی مستقل، رندر واقعی، انتخاب رشته‌ای اتاق، انتخاب از هندسهٔ Group، focus، overview، capture تصویر و dispose تکراری/remount را از همان interface اجرا کرد. فایل ملک و route عمومی جدید ایجاد نشده است.

هندسهٔ builderها، اشیای مرجع، بافت‌ها، دادهٔ میزهای هر دو کافه و implementation موجود landing نسبت به snapshot ابتدای این تغییر byte-for-byte حفظ شدند. در بازبینی، بارگیری تنبل builder انتخابی و انتخاب فرزندان هدف‌های Group اصلاح شدند. renderer از Cafe، reflection و نام waypoint ورودی مستقل است.

این بررسی تأیید backend چندسازمانی، پرداخت، صندوق آفلاین یا مقیاس‌پذیری عملیاتی نیست؛ آن قابلیت‌ها هنوز پیاده نشده‌اند. آزمایش روی گوشی فیزیکی نیز در این نوبت انجام نشده است.

## افزوده‌شدن کاما بهشتی — ۲۳ اکتبر ۲۰۲۶

build تولید، lint، TypeScript و هر ۱۴ آزمون موفق شدند. دو آزمون تازه، اتصال نقاط بازدید از میان درهای گلخانه و امکان نزدیک‌شدن به تمام میزهای کاما را با نمونه‌برداری برخورد بررسی می‌کنند. هندسه و برخورد کاما از برگ مستقل است.

در مرورگر، ورود، حرکت از حیاط تا بار، نمای کلی، انتخاب میز ۸ و اطلاعاتش، نور شب، نمایش عرض ۳۹۰ و دانلود GLB بررسی شدند. رندر موبایل حدود ۱۸۷ هزار مثلث و بدون reflection pass بود؛ این عدد تضمین FPS دستگاه واقعی نیست. فایل GLB از نظر ساختار، منابع داخلی و متناهی‌بودن مختصات بررسی شد. خروجی GLB سقف باز و متریال دارد و نورپردازی نمایشگر را حمل نمی‌کند.

۱۴ تصویر رسمی محلی و منابع آن‌ها در `output/research/comma-beheshti/` نگه‌داری شده‌اند؛ preview برنامه از رندر ساخته شده و عکس پژوهشی داخل public قرار نگرفته است. نسبت ابعاد، پلان و چیدمان تخمینی است. طبقه بالا فقط در نمای کلی دیده می‌شود؛ تست گوشی فیزیکی و برداشت ابعاد انجام نشده‌اند.

## دستورها

```sh
npm run build
npm run lint
npm run check-types
npm test
```

آزمون مسیر‌یابی از interfaceهای `isWalkable` و `findPath` می‌گذرد و عبور میان همه نقاط را بررسی می‌کند. کنترل دستی: شروع، WASD، کشیدن، گوشی و جوی‌استیک، overview، روز/شب، راهنما، تم پایدار و خروج/ورود به صفحه.

## امنیت این فاز

catalog allowlist محلی است؛ slug نامعتبر not-found می‌دهد. هیچ endpoint رزرو، ثبت اطلاعات، پرداخت یا secret وجود ندارد. HTML پویا از داده کافه ساخته نمی‌شود. import صحنه از مسیر فایل ورودی کاربر resolve نمی‌شود. بررسی وابستگی production با `npm audit --omit=dev` انجام می‌شود؛ بسته‌های توسعه جدا بررسی شوند.

این سند گواهی امنیت نیست؛ Codex Security scan رسمی یا تست نفوذ انجام نشده است. پیش از قابلیت‌های عملیاتی، مجوز سازمان/شعبه، PII، تراکنش هم‌زمان، verify پرداخت و sync باید طراحی و آزمون شوند.

## شواهد اجرای این نوبت

تاریخ اجرا: ۲۰ اکتبر ۲۰۲۶.

| بررسی                            | نتیجه                                                                  |
| -------------------------------- | ---------------------------------------------------------------------- |
| `npm run build` از ریشه          | موفق؛ فهرست و کافه برگ prerender شدند                                  |
| `npm run lint` از ریشه           | موفق، بدون هشدار                                                       |
| `npm run check-types` از ریشه    | موفق برای space و UI                                                   |
| `npm run test --workspace space` | هر ۱۲ آزمون موفق                                                       |
| مسیر‌یابی                        | همه جفت‌های نقاط بازدید، مسیر نزدیک‌شدن به هر ۸ میز و برخورد با مبلمان |
| کنترل گوشی                       | ورود، نمایش جوی‌استیک، drag حرکت و drag نگاه در مرورگر بررسی شد        |
| رابط                             | نمای کلی، نور شب، راهنما، تم روشن و خروج/ورود مجدد بررسی شد            |
| کافه نامعتبر                     | صفحه not-found فارسی نمایش داده شد                                     |
| مستندات                          | لینک‌های محلی کنترل شدند؛ مرجع design.md با فایل ارسالی یکسان است      |
| audit تولید                      | صفر آسیب‌پذیری گزارش‌شده در زمان بررسی                                 |

شبیه‌سازی عرض گوشی انجام شده؛ تست روی گوشی فیزیکی و سنجش FPS دستگاه ضعیف هنوز انجام نشده است. مسیر WebGL error/retry در کد بازبینی شد و canvas تازه برای retry ایجاد می‌شود؛ خطای واقعی GPU عمداً تزریق نشده است. آزمون چندلمسی هم‌زمان روی سخت‌افزار واقعی باقی است.

در Next با streaming، حالت not-found یا redirect ممکن است پس از شروع پاسخ HTTP 200 نمایش داده شود؛ نتیجه UI و metadata باید بررسی شوند و status به‌تنهایی معیار این دو رفتار نباشد.

audit کامل workspace تعداد ۹ هشدار high زنجیره ابزارهای توسعه مربوط به `braces <=3.0.3` گزارش کرد. در registry بررسی‌شده نسخه اصلاحی 3.0.4 وجود نداشت؛ پیشنهاد downgrade عمده ابزارها خودکار اعمال نشد. منبع: [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm). پیش از تغییر زنجیره CLI/lint، راه‌حل سازگار جدا بررسی شود.

## سازگاری ابزارها

TypeScript ریشه، space و UI روی 5.9.3 هماهنگ شدند؛ parser نصب‌شده typescript-eslint نسخه 7.0 را نمی‌پذیرفت. React و React DOM مصرف‌کنندگان UI برابر 19.3.0 هستند. بسته UI از peer dependency برای React استفاده می‌کند. هیچ اصلاح خودکار با `audit fix --force` انجام نشده است.

## بازبینی Cosmos و انتخاب میز

رندر با عرض موبایل، انتخاب میز ۴ از فهرست، انتخاب میز ۷ از نشان مدل، ظرفیت و موقعیت، حرکت به کنار میز و تم روشن/تیره در مرورگر بررسی شدند. پنل در حالت افقی ارتفاع محدود و اسکرول داخلی دارد. در تست موبایل reflection غیرفعال و شمار مثلث‌های فریم حدود ۱۱۰ هزار بود؛ این عدد، تضمین FPS نیست. کنسول در مسیر بررسی‌شده خطا یا هشدار نداشت.

آزمون خودکار هر میز را از تمام نقاط بازدید دنبال می‌کند و مسیر را با نمونه‌های میانی از نظر برخورد می‌سنجد. آزمون بودجه، حذف reflection برای موبایل و دستگاه محدود و تشخیص افت پایدار به جای وقفه منفرد را بررسی می‌کند.

ابزار مرورگر این محیط `Input.dispatchTouchEvent` را پشتیبانی نکرد؛ بنابراین آزمون دو انگشتی هم‌زمان انجام‌شده محسوب نمی‌شود. drag و رهاشدن جوی‌استیک بررسی شدند؛ تست چندلمسی و FPS روی Android ضعیف و iPhone واقعی همچنان لازم است.

## جزئیات عکاسی و اکشن رزرو

مدل با یازده عکس ارسالی بازبینی شد؛ هندسه صندلی توری، لبه سنگی حوض، چوب‌های توخالی، درخت آویزدار، گلدان‌ها و نمای ورودی اصلاح شدند. تصویر preview از خروجی تازه خود نمایشگر گرفته شده است. موانع درخت، گلدان‌ها و جعبه جلوی حوض در مسیر‌یابی لحاظ شده‌اند؛ جای نقطه بازدید انتهای کافه با صندلی‌های تازه اصلاح شد. همه مسیرهای میز و نقاط بازدید آزموده شدند.

اکشن «رزرو این میز» روی میز انتخاب‌شده، روزهای محلی تهران با نمایش تقویم فارسی، ساعت نمونه و تعداد مهمان محدود به ظرفیت را نشان می‌دهد. انتخاب ساعت برای ادامه لازم است؛ خلاصه صریحاً می‌گوید چیزی ثبت یا ارسال نشده است. هیچ فرم هویت، API یا موجودی زنده اضافه نشده است. آزمون‌ها عبور نیمه‌شب تهران و پایان سال، انتخاب نامعتبر و بودجه هندسه تکرارشونده صندلی را پوشش می‌دهند.

نمایش رزرو در عرض‌های ۳۹۰ و ۳۲۰ پیکسل شبیه‌سازی شد؛ دکمه‌های تعداد مهمان روی موبایل سه‌ستونه‌اند و پنل کوتاه اسکرول داخلی دارد. انتخاب ۶ نفر برای میز گروهی، مرور خلاصه و بازگشت به میزها بررسی شدند. در نمای کلی موبایل این نسخه، reflection خاموش و فریم نمونه حدود ۶۴ هزار مثلث داشت؛ مقایسه FPS یا تضمین دستگاه واقعی ادعا نمی‌شود. حالت روز/شب و تصویر تازه مدل نیز بررسی شدند.

در توسعه، `allowedDevOrigins` فقط alias محلی `127.0.0.1` را علاوه بر localhost می‌پذیرد تا HMR و دارایی‌های توسعه روی آدرس دمو مسدود نشوند. wildcard یا دامنه عمومی اضافه نشده است.

## پنل Luma، منو و سفارش — ۲۴ اکتبر ۲۰۲۶

این وضعیت جایگزین محدودیت منو و سفارش در گزارش‌های تاریخی بالاست. ۴۲ آزمون موفق: ۱۲ HTTP واقعی Nest/PostgreSQL، ۲۲ space، ۴ نمایشگر مستقل و ۴ جهت وابستگی. build تولید space و API، lint، typecheck و `git diff --check` موفق بودند.

مرورگر روی نسخه production محلی: افزودن آیتم، ویرایش قیمت، ثبت ورود رزرو، انتخاب دو واحد با جمع ۲۵۰ هزار تومان، ثبت سفارش و تمام مراحل آماده‌سازی/تحویل بررسی شدند؛ وضعیت نهایی و مبلغ در PostgreSQL نیز تأیید شد. فقط رکوردهای موقت همین سناریو پاک شدند. منوی عمومی همان آیتم و قیمت به‌روزشده را از API نمایش داد. کنسول مسیر عمومی خطا یا هشدار نداشت.

عرض‌های ۱۴۴۰، ۳۹۰ و ۳۲۰، تم روشن/تیره و فرم موبایل بررسی شدند. در عرض ۳۲۰، عرض صفحه برابر viewport است و dialog منو با عرض ۲۸۸ داخل آن قرار می‌گیرد. رنگ primary روشن `#381ac9` و تیره `#a99bff` از تم موجودند؛ فایل‌های CSS تازه رنگ ثابت ندارند. مرجع و محدودیت ابزار تولید طرح در [گزارش طراحی](../design/cafe-workspace.md) ثبت شده‌اند. تست دستگاه فیزیکی یا تضمین بار تولید ادعا نمی‌شود.
