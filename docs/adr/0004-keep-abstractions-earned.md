# انتزاع‌ها بر اساس مصرف و تفاوت واقعی شکل بگیرند

با وجود برنامه گسترش چندصنفی، اکنون یک برنامه و یک صحنه داریم. module نمایش داخل `space` می‌ماند؛ package نمایشگر، adapter شبکه و interface عمومی همه صنف‌ها فعلاً ساخته نمی‌شوند. UI workspace موجود از همین فاز مصرف می‌شود و کافه جدید قالب route را کپی نمی‌کند.

این تصمیم KISS و DRY را با OCP متعادل می‌کند: حفظ locality امروز، استخراج seam مناسب پس از مشاهده تفاوت صحنه دوم. هزینه استخراج آینده پذیرفته شده؛ ساخت یک framework فرضی اکنون به جای حل مسئله، interface بزرگ‌تری به caller تحمیل می‌کرد.
