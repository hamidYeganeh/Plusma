# نمایش فضایی مستقل و تجربه‌های متعلق به هر صنف

کاربر پیاده‌سازی زیرساخت چندصنفی را درخواست کرد. وابستگی runtime به `Cafe`، شناسه عددی میز، navigation برگ و جزئیات reflection مانع مصرف آن برای ملک بود. اکنون `@repo/spatial` یک module مستقل با interface صحنه، هدف فضایی و lifecycle است؛ هیچ وابستگی به app، React یا قواعد کافه ندارد. بارگیری renderer و builder هر صحنه همچنان پویا است.

کاتالوگ، هندسه، ارتباط هدف با میز، پنل انتخاب و پیش‌نمایش رزرو در module کافه می‌مانند. adapterهای برگ و کاما implementation موجود هندسه را پشت interface مشترک قرار می‌دهند. fixture مسکونی همان interface را با شناسه اتاق، نقطه شروع متفاوت و هدف گروهی بررسی می‌کند؛ فایل ملک یا مسیر عمومی جدید محسوب نمی‌شود.

این تصمیم بخش «نمایشگر داخل app بماند» در ADR-0004 را جایگزین می‌کند. استخراج بر اساس مصرف واقعی، public interface کوچک و پرهیز از moduleهای خالی همچنان برقرار است. درخواست چندصنفی، تغییر دامنهٔ دمو به رزرو یا پرداخت عملیاتی نیست؛ backend، دسترسی سازمانی، ذخیره‌سازی، صف و صندوق آفلاین در فازهای عملیاتی پیاده می‌شوند.

جهت وابستگی با بررسی importهای resolveشده، interfaceهای عمومی moduleها و exports بسته enforce می‌شود. تست‌ها public interface نمایش را با هر دو adapter فعلی و fixture مستقل پوشش می‌دهند. هزینهٔ این تصمیم یک workspace بیشتر و حفظ قرارداد بین صحنه و نمایشگر است؛ در عوض معنای تجاری انتخاب‌ها وارد موتور مشترک نمی‌شود.

به‌روزرسانی ۲۴ اکتبر: تعویق رزرو backend با [ADR-0006](0006-operational-reservations.md) جایگزین شد؛ استقلال نمایشگر پابرجاست.
